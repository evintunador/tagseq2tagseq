## Notes
- **decao2019entitygcn** — Entity-GCN: builds a graph over mention nodes (same-doc / match / coref edges) across the WikiHop candidate documents and runs a GCN (R-GCN style) to propagate for multi-hop answer selection. Purest "read across documents by message-passing on an explicit cross-doc entity graph" precursor to TS2TS's cross-doc attention edge — but the graph is a *separate GNN module* over pre-encoded mentions at *inference/task* time, edges = coref/string-match not hyperlinks, and there is no LM pretraining on the structure. TS2TS instead makes the cross-doc edge a *self-attention grant inside one decoder sequence*, trained end-to-end.
- **song2018mhqagrn** — Coref-GRN / MHQA-GRN: constructs graph-structured passage representations (evidence nodes linked by coreference and same-document/sliding-window edges) and applies a Graph Recurrent Network to encode them before answer prediction. Same era/idea as Entity-GCN (GNN reader over an explicit evidence graph); contrast is identical — external graph-encoder module, not an attention edge inside a pretrained LM.
- **kundu2019pathnet** — PathNet: explicitly extracts and scores *reasoning paths* (entity chains connecting question to candidate through intermediate passages), then aggregates path representations. Path-following is done as a discrete extraction + neural scoring step over documents. TS2TS's link-following is architecturally analogous (a generated link fetches the target doc), but is realized as a learned attention grant used in both pretraining and generation rather than an external path-enumeration pipeline.
- **min2019decomprc** — DecompRC: decomposes a HotpotQA multi-hop question into single-hop sub-questions via a span-based pointer, answers each with an off-the-shelf single-hop RC model, and rescores decompositions. Canonical *question-decomposition* multi-hop baseline. Purely inference-time symbolic decomposition; no shared representation across hops and no training on link structure — orthogonal to TS2TS's structural inductive bias, useful as the "decompose instead of link" contrast.
- **wei2022cot** — Chain-of-thought prompting: elicits intermediate reasoning steps from a frozen large LM by few-shot exemplars; multi-hop capability is emergent from scale + prompting, with no retrieval and no graph. The reasoning happens entirely in-context in the generated token stream. Frame TS2TS as supplying the *right documents into context via a trained link edge* rather than relying on parametric knowledge + verbalized reasoning.
- **zhou2023leasttomost** — Least-to-most prompting: prompt the LM to reduce a complex problem to an ordered sequence of easier subproblems solved sequentially, each conditioned on prior answers. Inference-time compositional prompting; contrast with TS2TS is the same as CoT/DecompRC — decomposition in the prompt vs. a trained cross-doc attention pathway.
- **khot2023decomp** — Decomposed Prompting: a modular framework where a controller LM dispatches sub-tasks to specialized handler prompts/tools (including recursive decomposition). More systems-level than CoT; still purely inference-time orchestration of a frozen LM with no learned structural edge and no pretraining on linked corpora.
- **xiong2021mdr** — Multi-hop Dense Retrieval (MDR): iteratively re-encodes the question *plus already-retrieved passage* to retrieve the next hop with a shared dense bi-encoder, enabling open-domain multi-hop QA. Closest *learned iterative-retrieval* analogue: the query-plus-retrieved reformulation mirrors link-following, but hops are separate MIPS lookups against an external index with a trained retriever, whereas TS2TS resolves the next hop *in-sequence* through the attention grant (no retriever, no re-encode).
- **zhang2024beamretrieval** — End-to-End Beam Retrieval: jointly models the entire multi-hop retrieval process, keeping a beam of relevant-passage hypotheses across hops and training the encoder end-to-end (SOTA on HotpotQA/MuSiQue retrieval). Still an external retrieve-then-read pipeline over a passage index; contrast TS2TS which folds hop chaining into the LM's own forward pass via graph edges rather than a beam over retrieval candidates.
- **edge2024graphrag** — Microsoft GraphRAG: LLM extracts an entity–relation *knowledge graph* + community summaries from the corpus offline, then answers query-focused/global questions by map-reduce over graph communities. Uses graph structure for multi-hop/global synthesis, but the graph is LLM-*constructed* and consumed at *inference* as retrieved text; TS2TS uses the corpus's *native* link structure (hyperlinks/imports/citations) as a *training-time* attention topology. Key contrast: derived-graph-at-inference vs. native-graph-in-pretraining.
- **gutierrez2024hipporag** — HippoRAG: builds an open KG over the corpus and, at query time, runs Personalized PageRank seeded by query entities to retrieve a multi-hop-relevant subgraph in a single retrieval step (hippocampal-index analogy). The strongest "graph structure for multi-hop memory" baseline: PPR over an explicit KG substitutes for iterative retrieval. Contrast — the graph and PPR are an external non-parametric memory queried at inference; TS2TS bakes graph proximity into sequence packing and the attention mask during pretraining, so multi-hop access is a learned in-context edge, not a PPR walk.
- **yu2024chainofnote** — Chain-of-Note: RALM generates sequential reading *notes* per retrieved document before answering, improving robustness to noisy/irrelevant retrieval and unanswerable queries. Relevant to the *reliability of cross-doc reading* rather than the retrieval/link mechanism; positions against TS2TS as an inference-time note-taking robustness layer over standard RAG, whereas TS2TS addresses which doc enters context via the trained link.
